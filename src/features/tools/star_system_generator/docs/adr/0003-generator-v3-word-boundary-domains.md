# Generator Version 3 matches Narrative Domains on word boundaries

Version 2 tagged Narrative Facts with Narrative Domains by substring match, so `maintenance` and `failure` read as `ai`, `isolated`, `solar` and `sold` read as religion (`sol`), `gold`, `cold` and `hold` read as archaeology (`old`), and `dwarf`, `swarm` and `warning` read as war. Those tags feed the Relationship Graph, so the wrong ones change the Spine, the System Story and Stories at Port. The fix cannot be made additive: matching only `ai`, `sol` and `old` on word boundaries already changed 185 of the 200 golden cases. So we made a deliberate break. Version 3 is now the current Generator Version, and Version 2 is kept unchanged, so v2 and v-less Seed Links (ADR-0002) still reproduce exactly.

- Version 3 changes one thing: how the classifier matches words. The 22 rule groups, their order and the domains they assign are the same as in Version 2. A term matches only as a whole word, and hyphens count as word boundaries (`narrow-ai`, `sol-interdiction`). It also matches its regular plural: `s`, or `es` after s/x/z/ch/sh. Inflected forms that v2 caught by accident and that belong to the domain are listed explicitly (`laboratory`, `chirality`, `terraforming`, `governance`, `refueling`, `illegal`, `outlaw`, `charted`, `traders` and others). We kept no trap word (`maintenance`, `market`, `calibration`, `charter` as exploration, `culture`, `mineral`, `interstellar`). The audit also removed these traps: `ore`, `ark`, `gate`, `ration`, `war`, `lab`, `law`, `cult`, `chart`, `mine`, `stellar`, `anchor`, `draft`, `claim`, `route`.
- Version 3 only removes tags. A corpus test checks that, for every classifier input, the v3 domains are a subset of the v2 domains, except where v3 falls back to `public-life` because nothing matched.
- Lowercased camelCase tags and kinds (`sceneAnchor`, `routeAsset`, `hiddenTruth`) no longer leak their embedded words. Encounter sites lose an accidental exploration/trade tag. Hidden truths keep espionage through their explicit `secret` tag.
- Measured on the 200 golden cases with the version stamp normalised, 190 of 200 systems differ from Version 2.
- Version dispatch has one seam. `lib/generator/rules.ts` maps each Generator Version to its `GeneratorRules`. `generateSystem` resolves the rules once and stamps `rules.version`; an unknown runtime value resolves to the current version. Code below `generateSystem` receives the rules or a rule function, never a version number. The next version-dependent change (Q30 hook variety) adds a field to `GeneratorRules` and an entry per version.
- The golden guard keeps one fixture per version. `STAR_SYSTEM_GOLDEN_UPDATE=1` rewrites only the current version's fixture; a superseded version's fixture is frozen and must never be regenerated.
- The default audit profile runs the current version. The last Version 2 audit run (default profile, before this change) recorded 722 errors; Version 3 records the same 722, so the error baseline is unchanged. Only relationship edge mix moves slightly. Nothing audits Version 2 any more, because its output is frozen by its golden fixture.

## Considered Options

- **Fix in place and regenerate the golden fixture**: rejected, because ADR-0002 exists so that shared links survive changes like this.
- **Branch on the version inside the classifier**: rejected. Each later version-dependent rule would add its own branch deep in the generator. The rules table keeps the supported versions and their behaviour in one place, and Seed Link decoding reads its supported list from the same table.

## 2026-11-21: Version 3 also changes the Hook Selection Profile

Version 2 always treated GU and Bleed as Active Terms, so every system leaned toward GU- and Bleed-tagged Stories at Port entries and the Bleed patterns in `hooks/terms.ts` never changed anything. Version 3 has not shipped yet (the release hold on `main` stays), so the hook change goes into the same Generator Version instead of forcing a Version 4.

- `GeneratorRules` gains `hookSelectionProfile`. Version 2 keeps `HOOK_SELECTION_PROFILE_V2`, and its golden fixture is unchanged. Version 3 uses `HOOK_SELECTION_PROFILE_V3`.
- No Hook Term is always active in Version 3. GU becomes active when the modified GU Intensity roll is above the Geometrically quiet band (`intensityRoll > guIntensityTable[0].max`). That is the same threshold that names the intensity, so the signal and the displayed intensity always agree. Bleed becomes active only through its own patterns. Every intensity band above quiet except the shear and fracture bands names a bleed (`Low bleed`, `Useful bleed`, `Rich bleed`), so those systems get Bleed from the intensity text. Quiet, shear and fracture systems get Bleed only if their bleed location, behaviour, settlements or phenomena use bleed vocabulary. We considered gating Bleed on GU, but rejected it: a quiet system whose text describes a calibration scar or a moving node still shows the referee a bleed. GU detection is shared with Version 2, where it changes nothing because Version 2 already forces GU on.
- Counts and bias are unchanged (contract 1, NPC 2, encounter 1, rumor 3, twist 1). Encounters now feed resonance, and rumors now prefer Resonant Terms instead of Active Terms, so rumors echo the contract, NPCs and encounter already drawn. The fork labels do not change.
- When a system has no Active Terms, steps that prefer Active Terms skip the bias draw and pick uniformly. Resonant steps still lean on the terms carried by earlier picks. In the 200 golden cases, one system has no Active Terms.
- Measured on the 200 golden cases (1,600 picks per version): GU is active in 186 systems and Bleed in 176. GU- or Bleed-tagged picks fall from 39.0% to 36.5%. Distinct pool entries used rise from 275 to 276 of 281. The effective number of entries (exp of the pick entropy) rises from 238.8 to 241.5, and the most-used entry falls from 16 picks to 15. The gain is small because most generated systems do have GU. Further variety needs new pool entries or tone gating, not profile changes.
- 86 of the 200 Version 3 golden hashes changed, and the Version 3 fixture was regenerated. The default audit still records 722 errors, so the error baseline is unchanged.
